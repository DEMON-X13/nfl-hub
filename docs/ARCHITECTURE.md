# The map

Deeper reference than `CLAUDE.md`. Read that first for the build loops and the
working agreement; read this when you need to find something or need the
vocabulary. It is a map, not a copy of the code -- the code is the truth, and
anything here that contradicts it is out of date.

## What this is

One repo, three independent single-page apps, served straight from the repo root
by GitHub Pages. No server, no database, no framework, no bundler. Each app is
one big self-contained HTML file with its data baked in; scheduled GitHub
Actions rebuild them from free data sources and commit the result.

`index.html` at the root is a static landing page linking the three.

```
betting/   X NFL Betting Model    game picks, win probabilities, power ratings
props/     Prop Model             player props, correlated parlays
news/      Season Tracker         newsletter-style week-by-week site
```

Everything a visitor does -- picks, parlays, bankroll, bets, odds they load --
lives in their own browser's local storage and never reaches the repo. Only a
commit changes what anyone else sees.

## Bets and Stats: one page over both models

`nflbets/` (X NFL Bets and Stats) is the page the two sites are migrating into, one tab at a time, so that
either can be reverted to on its own. `nflbets/build/build.js` assembles the prop model
from its parts (title, heading and tab bar swapped; every prop model section kept in the
page, listeners and all, whether or not it has a button yet), sets the Pick'ems board in
front of it from `nflbets/build/tab_pickems.html` (its own section, styles and closure,
every class and id prefixed `pk-`), and frames the betting site's Records, Power Ratings
and Bet Log tabs from `betting/admin.html?embed=1#tab`, which hides that page's header
and tab bar. The board's tag and confidence bands are lifted from the betting app at
build time and scoped inside the closure, since the prop model has its own `tag()`.
The prop model's tabs run on the prop model's own state under its own storage key, and
the framed tabs on the betting site's, so a pick, parlay or bet made on either site is
what this page shows. Tabs are addresses: `#slate`, `#parlay`, `#record` and so on.
`nflbets/build/smoke.js` boots the built page in jsdom against both sites' published
data and walks every tab.

## Props: how it fits together

```
nflverse CSVs + the-odds-api  ->  weekly.py  ->  data/payload.json
part1.html + payload + part2.js + part3.js  ->  assemble.py  ->  app/prop_model_2026.html
                                            ->  audit.js  (must be clean, or no commit)
                                            ->  publish.js ->  index.html + admin.html
```

`payload.json` is injected as `const PAY = {...}` at the top of the app, so every
number the page shows is already in the file when it loads. Its keys: `sched`
(272 games), `players` (473, each with seeded EWMA stat history), `toff`/`tdef`/
`tdefg` (team offence, defence, defence-by-position), `mkt` + `mkt_meta` (real
main lines per week), `prices` (raw odds rows per week), `stats` (actual results
per week), `corr` (the 329-entry pair correlation table), `model`/`grid`/`dist`/
`prior`/`pts`/`tdrate` (fitted model pieces), `injuries`, `depth`, `baked_at`.

`S` is the live state object, built by `freshState()` in `part2.js` from `PAY`
and then updated as weeks are ingested. It holds `players`, `teams`, `defs`,
`sched`, `processed`, `actuals`, `projections` (frozen pre-game numbers), plus
the visitor's own `parlay`, `saved`, `odds`, `stake`, `margin` and `ui`. `S` is
what gets serialised to local storage -- anything that must not persist has to
live outside it.

Tabs: **Games** (`slateView` + the `gameModal` overlay), **Parlay Builder**
(`parlayBody`), **Track Record** (`trackBody`), **Weekly Update** (admin only),
**Backup**.

### Vocabulary

- **leg** -- one line on a parlay. Keyed `gid|pid|stat` (`legKey()`), plus a
  threshold `k` and a `side` (`over`/`under`). One line per player per stat.
- **main line** -- the real sportsbook over/under for a stat (`main:true`).
- **rung** -- a step on a **threshold ladder**, the "10+, 20+, 30+" style
  alternatives (`LADDER` in `part2.js`). Hidden behind a checkbox by default.
- **game bets** -- `ml` (to win) and `ats` (to cover), one team bet per game,
  `grp:'TEAM'`.
- **corr vs indep** -- `parlayProb()` returns both: `indep` is the legs
  multiplied naively, `corr` is a gaussian-copula Monte Carlo over the shipped
  pair correlation table. `corr` is the number the UI shows. It is seeded, so it
  is deterministic.
- **SGP pricing** -- `parlayDec()`. Legs sharing a game are priced as one
  same-game parlay (never longer than multiplying), legs across games multiply.
- **margin** -- the book's cut, `light`/`typical`/`heavy`, a visitor setting.
- **suggested parlays** -- two engines. `buildSuggestions()` is the week-wide
  Safe/Medium/Aggressive tiers in the Parlay Builder, each tier growing the one
  before. `gameSuggestion()` is one Medium parlay for a single game, at most
  three legs, cached per game. `shuffleSuggestion()` deals an alternative at the
  same confidence, held outside `S` so it is forgotten when you leave the game.
- **liveWeek / weekOpen** -- the first week with an unfinished game; a later week
  is not "open" and shows fixtures only, because projections need recent form.
- **locked** -- kickoff has passed; the game stops accepting picks.

### The audit is a gate, not a test suite

`weekly.py` refuses to commit when `audit.js` is not clean, so a failing check
means the site silently stops updating and the scheduled run is marked failed.
Write checks against the app's invariants, never against whatever that week's
data happens to offer.

## Betting: how it fits together

The app is developed in a separate repo (`nfl-model-lab`) and shipped here as
one HTML file. `update.js` runs that real app headlessly in jsdom, through the
same upload path the owner would use by hand, starting from the last published
`state.json`, and writes the new state with the private parts stripped (bets,
bankroll, the owner's picks). It is idempotent: already-graded games are skipped,
games whose stats are not out yet wait for the next run.

`state.json` holds `teams`/`teamsH` (power ratings), `schedule`, `processed`
(graded games), `odds` (moneylines from nflverse, so Parlay Builder works with no
fetch), `qb`, `injuries`, `depth`, `joker`, `published`.

**The Joker** (`betting/joker/`) is a separate gradient-boosted-trees model,
fitted 2019-2025, whose per-game picks ship in `joker.json` and show next to the
main model's.

Gate: the app's embedded model numbers must equal `reference_models.json` or the
publish aborts. Shipping a model change means passing the release gate in
`nfl-model-lab`, then copying both the app and `reference_models.json` here.

Tabs: AI Picks, My Picks, Parlay Builder, Records, Bet Log, Power Ratings, Data
Upload, Backup. The public viewer drops Data Upload, Records and Bet Log.

## News: the half that is not automated

`pull-week.js` refreshes scores, records and stat bars from ESPN and
TeamRankings, and drafts `data/weekN.js`. **The narrative is written by a
person.** A draft is not live until it is added to `data/weeks.js` and
`index.html`. Read `news/HANDOFF.md` before touching anything here.

## Workflows

| Workflow | When | Does |
|---|---|---|
| `props.yml` | 12x/week: 4 price pulls (Mon/Wed/Thu/Sat), 8 post-game and stats runs | `weekly.py`, then `publish.js`, commits to `main` |
| `update.yml` | Fri/Mon/Tue mornings ET, with an afternoon catch-up each | betting `update.js` + `build.js` |
| `news.yml` | Fri/Mon/Tue 8am ET | `run-auto.js` |

Only `props.yml` spends money (`ODDS_API_KEY`, ~7 credits a game, ~112 a week,
500 free a month). The other two use free sources.

## Gotchas

- Editing a generated file is wasted work: the next scheduled run overwrites it.
  Change the source and rebuild.
- `props/app/app.js` is a build leftover and gitignored. Delete it after
  assembling.
- `betting/app/x_nfl_betting_model.html` looks generated but is **source**.
- The props audit needs `npm ci` in `props/build/` first.
- `parlayProb()` is seeded and deterministic; don't assume Monte Carlo noise
  explains a changed number.
